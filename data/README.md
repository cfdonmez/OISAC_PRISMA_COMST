# 🗄️ Data Storage

This is the central data warehouse for the O-ISAC Systematic Review. It follows a strict data flow pipeline from raw retrieval to structured output.

---

## 🔄 Data Pipeline Flow

| Stage | Directory | Description |
|-------|-----------|-------------|
| **1. Input** | **[`retrieved_docs/`](retrieved_docs/)** | **Raw PDFs.** The single source of truth for original files. Named `O_ISAC_XXX.pdf`. |
| **2. Prep** | **[`processed_markdowns/`](processed_markdowns/)** | **Markdown + Images.** Results of Phase 1 (PDF→MD) and Phase 2 (Image Extraction). Each paper has its own subfolder. |
| **3. Output** | **[`extraction_results_v3/`](extraction_results_v3/)** | **Production Data.** Validated, structured JSON/CSV outputs from the extraction pipeline. |
| **4. Exp** | **[`extraction_results_v4/`](extraction_results_v4/)** | **Experimental.** Sandbox for testing new extraction schemas or models. |

---

## 📂 Subdirectory Details

### `retrieved_docs/`
*   Contains 150+ PDFs renamed to `O_ISAC_XXX.pdf`.
*   **Protocol:** Do not manually rename files here unless following [System Patterns](../memory-bank/systemPatterns.md).

### `processed_markdowns/`
*   Generated by `marker-pdf`.
*   Structure:
    ```
    O_ISAC_XXX/
    ├── O_ISAC_XXX.md       # Full text
    ├── visual_analysis.txt # Phase 2 Output (Image captions)
    └── O_ISAC_XXX/         # Extracted images (png/jpg)
    ```

### `extraction_results_v3/` (ACTIVE)
*   **`extraction_v3.json`**: The master dataset used for analysis.
*   **`checkpoint.json`**: Tracks which papers have been successfully processed to allow resuming.

### Other folders
*   `search_logs/`: History of query strings and hit counts from IEEE/Scopus.
*   `figures/`: Generated plots for the final manuscript.
*   `status/`: Tracking files for project management.
*   `legacy_archive/` (moved from root): Old datasets (v1/v2).

---

## ⚠️ Critical Rules
1.  **Never delete `retrieved_docs`**: It is expensive to re-download.
2.  **Read-Only Inputs**: Do not modify files in `processed_markdowns` manually; re-run the pipeline if needed.
3.  **Versioning**: Always create a new `extraction_results_vX` folder for major schema changes.
