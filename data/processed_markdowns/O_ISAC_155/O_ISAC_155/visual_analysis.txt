# O_ISAC_155 Visual Analysis

## 1. System Architecture (Fig. 2)
- **Framework**: Human-Enhanced Robot Orchestration (HERO).
- **Planes**:
    - **Physical**: Mobile robots running containerized microservices (SLAM, segmentation, JCAS).
    - **Control**: Application and Network Orchestration (ANO) for real-time scheduling based on battery, CPU, and network QoS.
    - **Virtual**: Cloud and Edge nodes for computational offloading.
    - **Human**: Dashboard and control interfaces for situational awareness.
- **Connectivity**: Multi-link (5G URLLC & Wi-Fi).

## 2. Real-Time Monitoring (Fig. 3a & 3b)
- **Dashboard (Fig. 3a)**: Visualizes fleet status for 6 robots (RM01-RM06).
    - **Metrics**: CPU load, GPU usage, Memory, and Battery levels (e.g., RM01 at 67% battery, RM06 at 38%).
    - **Status**: Indicates offloading decision (e.g., "Onboard in RMxx").
- **Visual Analytics (Fig. 3b)**: RViz based 3D point clouds, environmental maps, and semantic segmentation (e.g., human detection) generated by robots.

## 3. Performance Evaluation (Table I)
- **Strategies**:
    1. **Local**: All processes run on robot. Runtime: 15 min. Energy: 100%. Continuity: Interrupted.
    2. **Offload**: Constant offloading. Runtime: 37.5 min. Energy: 85%. Continuity: Partial.
    3. **Adaptive (HERO)**: Dynamic orchestration. Runtime: 60 min. Energy: 42.5%. Continuity: Full.
- **Key Results**: HERO extends runtime by 4x, reduces energy consumption by 57.5%, and lowers bandwidth usage by ~26%.

## 4. Hardware and Environment (Fig. 1)
- **Scenario**: Logistics warehouse with mobile robots transporting goods.
- **Autonomous Tasks**: Visual/LiDAR SLAM, 6G-driven JCAS for radar-based collision avoidance, and semantic environment segmentation.
