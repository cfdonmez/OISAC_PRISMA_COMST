For VIII-E, `deployment_convergence_roadmap` is a distinct bottleneck beyond standards, hardware, channel modeling, and security because deployment may still stall when sensing and communication functions are not co-integrated in practice. Evidence from VIPAC suggests that positioning-for-sensing and channel-estimation-for-communication can be integrated into a unified architecture, so convergence can behave as an implementation dependency rather than a purely algorithmic choice [O_ISAC_039]. This same evidence also motivates orchestration/state-fusion pressure, where joint task states may require coordinated handling at deployment time [O_ISAC_039]. A third motif is staged roll-out/readiness signaling: practical implementation and eventual roll-out may require multiple design issues to be addressed together, which supports phased readiness language in the roadmap [O_ISAC_163]. A fourth motif concerns transferability governance: open-source implementation hooks can improve reproducibility and cross-domain uptake, but still require governance on how results are interpreted across deployment settings [O_ISAC_200].
